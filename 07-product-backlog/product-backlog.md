# Product Backlog – CRM-Modernisierung

## 1. Ziel

Das Product Backlog enthält die priorisierten User Stories für die geplante CRM-Modernisierung.

Die Priorisierung erfolgt anhand der MoSCoW-Methode. Dabei werden fachlicher Nutzen, Bedeutung für die Kernprozesse und Abhängigkeiten berücksichtigt.

Da es sich um eine fiktive Fallstudie handelt, sind die Prioritäten begründete Annahmen und nicht durch einen realen Product Owner bestätigt.

## 2. Priorisiertes Product Backlog

| ID | User Story | Priorität | Begründung |
|---|---|---|---|
| US-01 | Kundendatensatz anlegen | Must have | Grundlegende Voraussetzung für die zentrale Verwaltung von Kundeninformationen |
| US-02 | Mögliche Dubletten erkennen | Should have | Unterstützt die Datenqualität und verhindert doppelte Datensätze |
| US-03 | Kundendaten bearbeiten | Must have | Erforderlich, damit Kundeninformationen aktuell gehalten werden können |
| US-04 | Kundeninformationen suchen | Must have | Grundvoraussetzung für den schnellen Zugriff auf vorhandene Kundendaten |
| US-05 | Kundenkontakt dokumentieren | Should have | Verbessert die Nachvollziehbarkeit der Kundenkommunikation |
| US-06 | Vertriebschance verwalten | Must have | Unterstützt die zentrale Verwaltung von Vertriebsaktivitäten |
| US-07 | Status einer Vertriebschance aktualisieren | Must have | Erforderlich, um den Bearbeitungsstand von Vertriebschancen nachvollziehen zu können |
| US-08 | Vertriebschancenübersicht einsehen | Should have | Verbessert die Transparenz für die Vertriebsleitung |
| US-09 | Benutzerberechtigungen verwalten | Must have | Notwendig für eine kontrollierte Verwaltung von Zugriffsrechten |

## 3. MoSCoW-Verteilung

### Must have

- US-01: Kundendatensatz anlegen
- US-03: Kundendaten bearbeiten
- US-04: Kundeninformationen suchen
- US-06: Vertriebschance verwalten
- US-07: Status einer Vertriebschance aktualisieren
- US-09: Benutzerberechtigungen verwalten

Diese Funktionen bilden den angenommenen Kernumfang der ersten CRM-Version.

### Should have

- US-02: Mögliche Dubletten erkennen
- US-05: Kundenkontakt dokumentieren
- US-08: Vertriebschancenübersicht einsehen

Diese Funktionen bieten einen wichtigen Zusatznutzen, können aber im Rahmen der Fallstudie nach den Kernfunktionen betrachtet werden.

### Could have

Aktuell wurden keine User Stories dieser Kategorie zugeordnet. Bei einer Erweiterung des Product Backlogs könnten beispielsweise zusätzliche Auswertungs- oder Komfortfunktionen aufgenommen werden.

### Won't have (this time)

Aktuell wurden keine User Stories dieser Kategorie zugeordnet. Die bewusste Abgrenzung weiterer Funktionen kann im Rahmen einer späteren Release-Planung erfolgen.

## 4. Abhängigkeiten

Folgende Abhängigkeiten sind bei der Umsetzung zu berücksichtigen:

- US-01 und US-03 bilden die Grundlage für die Anlage und Pflege von Kundendaten.
- US-02 ergänzt US-01 um eine Prüfung auf mögliche Dubletten.
- US-04 ermöglicht den Zugriff auf bestehende Kundendatensätze.
- US-06 ist die Grundlage für die Verwaltung von Vertriebschancen.
- US-07 setzt voraus, dass Vertriebschancen angelegt und verwaltet werden können.
- US-08 baut auf der Verwaltung und Statuspflege von Vertriebschancen auf.
- US-09 bildet eine wichtige Grundlage für die kontrollierte Nutzung der CRM-Funktionen.

## 5. Annahmen und Grenzen

Die Priorisierung wurde für eine fiktive Fallstudie vorgenommen. In einem realen Projekt müsste sie durch den Product Owner beziehungsweise die fachlich verantwortlichen Stakeholder bestätigt werden.

Die MoSCoW-Einstufung stellt keine technische Umsetzungsreihenfolge dar. Technische Abhängigkeiten, verfügbare Ressourcen und Risiken müssen zusätzlich berücksichtigt werden.

## 6. Nächster Schritt

Auf Basis dieses Backlogs wird eine beispielhafte Sprintplanung erstellt. Dabei werden ausgewählte User Stories einem Sprint zugeordnet und die Auswahl fachlich begründet.
